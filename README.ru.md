# Microstock+ для ИИ-агентов

Управляйте стоковым портфолио из Claude Code, ChatGPT, Codex, Cursor и любого MCP-совместимого агента. [Microstock+](https://microstock.plus) хранит фото, векторы и видео с метаданными и состоянием на стоках. Этот комплект подключает агента к аккаунту владельца через Agent API.

С плагином Claude может:

- **Проверить папки**: найти файлы без названия, описания или ключей, с недостаточным числом ключей или с ошибками валидации на стоках.
- **Написать и улучшить атрибуцию** по правилам каждого стока, показать каждое изменение заранее и сохранить только то, что вы одобрили, не затирая правки, сделанные тем временем.
- **Проверить статусы и отказы** на каждом стоке — с причинами, которые назвал сток.
- **Выгрузить CSV** в бесплатных форматах «Экспорта CSV» из «Моих файлов».
- **Следить за изменениями**, которые он делает, через ленту событий.
- **Смотреть превью прямо в агенте** как защищённые MCP image-блоки; для клиентов без поддержки image-блоков есть пятиминутная запасная ссылка на `microstock.plus`, без токенов и DNS CDN.
- **Загружать локальные файлы** напрямую в существующую папку Microstock+ по короткоживущему upload ticket.

Платные ИИ-действия Microstock+ не входят в эту интеграцию. Смена статусов стоков требует отдельного скоупа `status:write`, а постановка в очередь — явного подтверждения пользователя.

Удалить через плагин ничего нельзя; удаление остаётся ручным действием в веб-интерфейсе Microstock+.

## Как пользоваться

Просите своими словами, например:

- «В каких файлах в /foto/2026 нет ключей или что не примет Shutterstock?»
- «Напиши названия и ключи для новой осенней папки, под Adobe Stock и Shutterstock».
- «Найди в /foto/2026 файлы без категорий и подбери подходящие».
- «Сократи тайтлы длиннее 200 символов в /foto/2026, сначала покажи пробный прогон».
- «Какие файлы отклонили на Adobe Stock и почему?»

В Claude Code есть и команды:

- `/microstock-plus:audit <папка>` — отчёт о пустой и слабой атрибуции, ничего не меняет.
- `/microstock-plus:keywords <папка или iids> [указания]` — пишет или улучшает атрибуцию, с превью перед сохранением.
- `/microstock-plus:export <папка или iids> [формат] [разделитель]` — сохраняет CSV с атрибуцией.

## Что внутри

| Компонент | Что делает |
| - | - |
| MCP-сервер `microstock-plus` | `server/mplus-mcp.mjs`, локальный stdio-сервер на Node.js без зависимостей: портфолио, превью, метаданные, upload ticket, CSV и события. `--dump-tools` выдаёт канонический каталог инструментов для удалённого шлюза. |
| Навык `mplus-portfolio-management` | Аудит, статусы и причины отказов, выгрузка CSV, отслеживание событий и что делать при сбоях. |
| Навык `mplus-keywording` | Названия, описания, ключи и категории по правилам стоков, ИИ-контент и батчи с пробным прогоном. |
| Команды `audit`, `keywords` и `export` | Быстрый запуск трёх самых частых задач. |
| `docs/AI_AGENT_SKILLS.ru.md` | Полное руководство для ИИ-агентов (английская версия — `docs/AI_AGENT_SKILLS.md`, опубликована на https://microstock.plus/ai-agent-skills/skill.md). |
| `openapi/agent-api-v1.json` | Описание Agent API в формате OpenAPI 3.1. |

## Установка

### Claude Code

Самое простое подключение использует облачный MCP и открывает OAuth-вход Microstock+ в браузере:

```bash
claude mcp add --transport http microstock-plus https://microstock.plus/mcp
```

Команды маркетплейса ниже нужны только для установки упакованных skills и slash-команд. Публикация в публичном каталоге требует отдельной проверки и здесь не заявляется.

Добавьте маркетплейс, где лежит плагин, и установите его:

```bash
claude plugin marketplace add eschota/microstock-plus-claude-plugin
claude plugin install microstock-plus@microstock-plus
```

Так устанавливаются упакованные skills и удалённый OAuth MCP из [GitHub-маркетплейса Microstock+](https://github.com/eschota/microstock-plus-claude-plugin). Репозиторий уже публичный и устанавливается напрямую; публикация в официальных каталогах Claude или OpenAI требует отдельной модерации и здесь не заявляется. Для локальной проверки checkout в одной сессии запустите `claude --plugin-dir ./microstock-plus-agent-kit`.

Коннектор — локальный MCP-сервер, ему нужен [Node.js](https://nodejs.org) 18 или новее. Он использует только встроенные модули Node и ничего не устанавливает.

### Ключ агента

Облачный MCP использует OAuth и не просит копировать агентский ключ. Для опционального локального stdio-сервера войдите на [microstock.plus/ai-agent-skills](https://microstock.plus/ai-agent-skills), создайте ключ с нужными скоупами и храните его только в защищённой конфигурации MCP-клиента. `status:write` и `files:upload` выдаются отдельно; платные AI-скоупы недоступны.

Отозвать ключ можно на той же странице в любой момент.

### ChatGPT и Codex

В ChatGPT включите Developer mode в **Settings → Security and login**, откройте **Apps** или **Plugins** (название зависит от поверхности и аккаунта), нажмите **+** и подключите `https://microstock.plus/mcp`. При первом доступе откроется OAuth Microstock+. Пакет для ChatGPT/Codex описан файлами `plugin.json`, `mcp.json` и `skills/`; он готов для прямой проверки, но ещё не отправлен в публичный каталог плагинов.

В Codex или другом клиенте с поддержкой remote MCP подключите тот же URL и завершите OAuth. Локальный Node stdio-сервер остаётся для клиентов, которым удобнее агентский ключ.

### Claude Desktop, claude.ai и Cowork

Плагины, добавленные на claude.ai в Customize › Plugins, появляются и в приложении, и в Cowork, но там загружаются только навыки и команды: чат не запускает локальные MCP-серверы, а Cowork пропускает сервер, которому нужна настройка плагина, потому что не спрашивает её значение. Чтобы инструменты работали в приложении Claude, добавьте сервер в `claude_desktop_config.json`, как описано в [docs/AI_AGENT_SKILLS.ru.md](docs/AI_AGENT_SKILLS.ru.md#подключение).

### Другие ИИ-инструменты

Сервер работает с любым MCP-клиентом: Cursor, OpenAI Codex CLI и другими. В [docs/AI_AGENT_SKILLS.ru.md](docs/AI_AGENT_SKILLS.ru.md#подключение) есть готовые конфигурации и описание обычного HTTP API для агентов без MCP.

## Данные и приватность

- **Куда уходят данные.** Сервер обращается только к Agent API Microstock+, `https://microstock.plus/api/agent/v1`, по HTTPS, с ключом агента в заголовке `Authorization` и user agent `microstock-plus-mcp/<версия>`. Ключ никуда больше не отправляется: сервер не скачивает ссылки с других хостов и не работает с адресом API без HTTPS.
- **Что отправляется.** То, что нужно инструменту: пути папок, id файлов, текст поиска, правки атрибуции и параметры выгрузки.
- **Что видит Claude.** Атрибуцию ваших файлов, статусы, сообщения валидации, ссылки на превью, запрошенные выгрузки CSV и данные аккаунта: тариф и подключённые стоки.
- **Что остаётся на компьютере.** Ничего. Сервер ничего не хранит и не пишет файлы; Claude сохраняет CSV, только когда вы об этом просите. Диагностика идёт в стандартный поток ошибок сервера и никогда не содержит ключ — только его публичный префикс из 8 символов. Аналитики и телеметрии нет.
- **Что записывает Microstock+.** Каждый вызов попадает в журнал аудита вашего аккаунта с префиксом ключа, а изменения агента сразу видны в «Моих файлах».

## Безопасность

- **Никаких удалений.** Инструмента для удаления нет; сервер никогда не отправляет запрос `DELETE`, а API на любой такой запрос отвечает `405 deletion_not_supported`.
- **Весь портфель с превью.** `mplus_list_files` по умолчанию включает подпапки; переходите по `next_cursor` до конца, затем вызывайте `mplus_get_previews` батчами до 8 IID. Визуальные MCP-клиенты получают image-блоки. В DTO файлов приходят только короткоживущие запасные ссылки на `microstock.plus`, а не адреса preview CDN; после истечения ссылки повторите вызов.
- **Уточнять ключи для iStock.** Получите кандидатов словаря Getty, выберите предложенные ID по реальному превью, сделайте dry run и сохраните одобренный владельцем выбор. Это не платный ИИ-вызов.
- **Никаких трат.** Платные AI quote/run инструменты этот комплект не публикует.
- **Только прямая загрузка.** Инициализация принимает сведения о локальном файле (`filename`, размер, MIME-тип и папку), но никогда не принимает URL удалённого источника.
- **Контролируемая отправка на сток.** `queued` отправляет файлы на один сток и допускается только после одобрения точных файлов и стока с `user_confirmed: true`.
- **Никаких потерянных правок.** Батчи атрибуции сначала проходят пробный прогон, а `if_match_metaver` не даёт Claude затереть правки, сделанные после того, как он прочитал файл.
- **Только ваш аккаунт.** Ключ работает в аккаунте владельца и с меньшими правами, чем у владельца; отозвать его можно в любой момент.

## Если что-то не работает

- **Claude говорит, что инструментов Microstock+ нет.** В Claude Code выполните `/mcp` и проверьте, что сервер `plugin:microstock-plus:microstock-plus` подключён. Если он не запустился, проверьте, что `node --version` в терминале, из которого вы запускаете Claude, показывает 18 или новее, и перезапустите сессию. В чате claude.ai и в Cowork сервер не запускается; см. [выше](#claude-desktop-claudeai-и-cowork).
- **«No Microstock+ agent key is configured».** Это относится только к опциональному локальному stdio-серверу. GitHub-плагин и облачный MCP используют OAuth в браузере и не требуют вставлять ключ.
- **`invalid_api_key` или `revoked_api_key`.** Ключ введён с ошибкой, перевыпущен или отозван. Создайте новый на [microstock.plus/ai-agent-skills](https://microstock.plus/ai-agent-skills) и введите его снова.
- **`scope_required`.** У ключа нет нужного разрешения. Создайте ключ с нужным скоупом.
- **«Not available yet» (пока недоступно).** Смены статусов и ИИ-атрибуции в Agent API пока нет; инструменты так и отвечают, ничего не пробуя.
- **`404 not_found` на любой вызов.** Agent API ещё не включён для вашего аккаунта: ключи агентов открываются постепенно.
- **`rate_limited`.** На ключ — 120 запросов и 30 изменений в минуту. Сервер сам подождёт и повторит один раз; для больших задач попросите Claude работать батчами до 100 файлов.
- **«Could not reach Microstock+».** Проверьте интернет и что прокси или файрвол пропускают HTTPS к `microstock.plus`.
- **Подробности.** Переменная окружения `MPLUS_MCP_DEBUG=1` там, откуда запускается Claude Code, включает запись каждого запроса к API (метод, путь, статус) в поток ошибок сервера.

## Разработка

```bash
node tests/smoke-test.mjs
```

Смоук-тест запускает `tests/mock-api.mjs` — мок Agent API в памяти по контракту `docs/AGENT_API_V1.md` — и гоняет сервер против него по stdio (MCP 2026-07-28 и более ранние ревизии) и по Streamable HTTP. Он проверяет все инструменты, защитные проверки и ошибки, а также файлы плагина и документ OpenAPI. Нужен только Node.js 18 или новее, подключения — только к `127.0.0.1`.

Для ручной проверки `node tests/mock-api.mjs --port 8787` запускает мок и печатает фейковые ключи на этот запуск. Направьте на него сервер: `MPLUS_API_BASE=http://127.0.0.1:8787/api/agent/v1` (обычный `http://` разрешён только для localhost) и один из напечатанных ключей в `MPLUS_API_KEY`.

`node server/mplus-mcp.mjs --help` показывает параметры, в том числе `--http <порт>`: Streamable HTTP на `http://127.0.0.1:<порт>/mcp` для клиентов, которым он нужен; тогда каждый запрос передаёт свой ключ в `Authorization: Bearer mpk_live_...`.
